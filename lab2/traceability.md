## Перевірка багато-до-багатьох

Трасування не є 1:1: `REQ-02` пов'язана з двома User Stories, `REQ-03` покривається трьома User Stories і двома сценаріями, а `REQ-04` перетинається з трьома сценаріями через повернення та оплату штрафу. Водночас `REQ-01` навмисно має лише пряме покриття окремим сценарієм автентифікації: використання авторизованої сесії як `Given` не підміняє тест авторизації.

`REQ-07` свідомо залишена непокритою. Модуль щомісячної аналітики виходить за межі поточного спринту та System Boundary Лабораторної роботи №2. Вимогу збережено для майбутнього планування, але Use Case і тестовий сценарій для неї наразі не створювалися.
