## Перевірка багато-до-багатьох

Трасування не є 1:1: `REQ-01` покривається трьома Use Cases, `REQ-02` пов'язана з двома User Stories, а `REQ-03` і `REQ-04` перетинаються через обробку штрафів. Один сценарій також перевіряє кілька вимог: сценарій 1 перевіряє `REQ-01`, `REQ-02` і `REQ-06`.

`REQ-07` свідомо залишена непокритою. Модуль щомісячної аналітики виходить за межі поточного спринту та System Boundary Лабораторної роботи №2. Вимогу збережено для майбутнього планування, але Use Case і тестовий сценарій для неї наразі не створювалися.
