# AI trace 02 — diagram review scope

**Фідбек після первинного результату:**

> Діаграми не показують явно, що запис `RESERVATION` відбувається лише після
> перевірок, а в негативній гілці не має бути виклику repository. Виправ ці
> логічні помилки в Mermaid-коді. Вхідні критерії в `spec.md` уточнено:
> persistence дозволена лише після всіх перевірок, а штрафна гілка не може
> викликати жоден repository для запису. Перевір Mermaid-код проти цих
> критеріїв і склади технічний список розбіжностей для аудиту. Також прибери
> окремий файл AUDIT.md — за критеріями в spec.md таблиця аудиту має бути
> розділом всередині самого spec.md.

**Виявлені розбіжності діаграм:**

1. Успішна діаграма не підкреслювала момент persistence після всіх перевірок.
2. Негативна гілка не мала явного доказу, що `ReservationRepository` не
   викликається.
3. Перевірку відповідності ER-моделі та Gherkin потрібно було зафіксувати
   окремим технічним списком для аудиту.
